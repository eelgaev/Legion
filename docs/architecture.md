# Architecture

Legion is a single crate (`legion`, lib + bin) using modules instead of multiple crates.

```
HTTP clients ──► src/server ──► src/engine (trait Engine) ──► engine impl (mock, lm on ggml CPU/CUDA)
 (OpenAI SDK,     routes/*.rs      GenerateRequest in,              │
  Anthropic SDK,  convert.rs       TokenEvent stream out            ├─ src/model, src/kv, src/hw
  open-webui,     error.rs                                          ├─ src/gguf.rs  (GGUF metadata, tensor infos)
  Claude Code)                                                      └─ src/ggml     (bindgen FFI to third_party/ggml)
```

| `src/engine/queue.rs` | The waiting queue both engines admit from: `--scheduling-policy` (FCFS or lowest `priority` first) and the per-key fair share. |
| `src/engine/lm.rs` | `LmEngine`, the model-neutral real engine, for every architecture in `src/model`: Qwen3.5 / 3.6 GGUF models (`qwen35`, `qwen35moe`), Qwen3.8-Flash-Next (Qwen4 architecture, `qwen4exp`), Nemotron-H (`nemotron_h`, `nemotron_h_moe`), Gemma 4 (`gemma4`) and Muse Glimmer (`muse-glimmer`) on the CPU or GPUs. |

| `src/engine/lm/response_format.rs` | Grammar-constrained sampling: the per-model grammar cache, each sequence's constraint (`response_format`, or strict tool calls between `<tool_call>` and `</tool_call>`), and the mask threads (`--grammar-threads`) that find the next mask during the forward pass. |
| `src/engine/lm/kv_vmm.rs` | `--kv-vmm` (#814): the GPU stages' KV pools made again in reserved virtual ranges, before the expert cache is sized; `--kv-vmm-keep` (`KvLend`) unmaps the pools' blocks past the kept tokens at load so the cache takes their VRAM, maps them again (after lending the cache) when the sequences need them and gives them back once they are free (under `--glm-parallel-decode` a long prompt maps them right after its lend, before its steps' buffers take that VRAM). #1196 keeps the pieces holding cached prefixes, warm sequences and saved tails past the kept blocks in pinned host memory mapped at the same addresses when the tail goes back (automatic, no flag: least recently used evicted past the budget, an eighth of the free host memory at most the tails), and copies them back into VRAM when a chat resumes them. Both on by default (32768 kept tokens) on a V100 layer split of 2 GPUs with the expert cache; `--no-kv-vmm` turns them off. |
| `src/engine/lm/preempt.rs` | `--kv-admission on-demand` (#627): admission on the prompt's KV blocks, growth before each step, preemption of the cheapest sequence by recompute and its resume. |
| `src/engine/lm/first_rows.rs` | An idle engine starts reading a new prompt's first chunk of n-gram (or Engram) table rows as the request arrives (#836), so the reads overlap admission, step preparation and the `--deterministic` gather window instead of the first step; the same bytes, so outputs do not change. |
| `src/engine/lm/even.rs` | `--prefill-even` (#758): a prompt that needs several steps takes them in equal parts instead of full steps and a short last one. |
| `src/engine/lm/slo.rs` | `--itl-target` / `--ttft-target` (#628): an online step-time model and each step's prompt budget from it, prompts at risk of their TTFT first. |
| `src/engine/lm/pipe.rs` | Decoding groups in flight over the pipeline stages (`--pipeline-groups`, #415): forming, rounds, draining. |
| `src/engine/lm/bandwidth.rs` | Each pipeline stage's bandwidth roofline at load, and the request-done line's model-bytes fields. |
| `src/engine/lm/vram.rs` | What the load leaves each GPU: the KV fit with the MTP head's own pool and a given `--expert-cache-gib`, the cache's size check, the kept step graphs' budget with host experts (#433). |
| `src/engine/lm/stream.rs` | Sequences' text (detokenizer, reasoning and tool-call parsers, log probabilities, the stream sends) on a thread of its own once `--stream-thread-seqs` sequences run (#47); stop-string and grammar requests keep theirs on the engine thread. |
| `src/engine/lm/vision.rs` | `--mmproj` (#146): a request's images as `<|image_pad|>` tokens (one per merged patch), the vision tower's rows and M-RoPE positions (`src/model/core/media.rs`) and a prefix-cache key that tells images apart. |
| `src/engine/lm/host_time.rs` | The engine thread's time per step by phase (plan, pack, step, sample, device calls, finish), logged at debug level as host microseconds per step (#47). |
| `src/engine/reasoning.rs` | Streaming `<think>...</think>` splitter: turns model text into `TokenEvent::Reasoning` and `TokenEvent::Text` events. |
| `src/engine/sampling.rs` | Token sampling from logits: penalties, temperature, top-k, top-p, min-p and a seeded RNG. |
| `src/engine/saved_states.rs` | Bookkeeping for saved recurrent states, the half of prefix caching that hybrid models need. |
| `src/engine/ring_checkpoints.rs` | Bookkeeping for saved sliding-window rings (context checkpoints), the half of prefix caching that ring models (Gemma 4) need; `--ring-checkpoints 0` turns them off (one copy per ring at its last prompt's end, as before). |
| `src/engine/stop.rs` | Stop-string matching over streamed text. |
| `src/engine/tool_parser/gemma4.rs` | Gemma 4 tool calls (`<|tool_call>call:NAME{...}<tool_call|>`, Gemma's argument notation). |

A small step's new graph is captured behind its first run (#827), an MTP take-in of several sequences (a shape that seldom comes back) only behind its second (`ReuseScope`, #836; `--no-stage-graph-capture-on-reuse` for off). `stage_graph/run.rs` keeps the captures; `stage_graph/stats.rs` counts runs, captures, kept graphs built and words changed (`--stage-graph-stats` logs them every 10 s, and each kept graph built with its shape and each words change with its first differing node, #858); `stage_graph/store.rs` keeps the captures by their graph's words, so a kept graph rebuilt with the same words launches the captures of the one before (`--stage-graph-cache`, 64 sets per GPU, #858); `stage_graph/spare.rs` keeps big dropped captures as spare executable graphs that a new capture of the same topology updates instead of instantiating (`--stage-graph-spare-execs`, 8 per GPU, #836), or one taken over from a kept capture idle for `--stage-graph-exec-steal-ms`, both only between captures with their thread-block-cluster kernels at the same nodes (`stage_graph/run/cluster_nodes.rs` reads them from the driver, #1132); for that `stage_graph/copy_kernel.rs` makes a big capture's device-to-device memcpy nodes copy kernel nodes (PTX `src/cuda/ptx/stage_copy.ptx`, the same bytes), which an update may move, and `stage_graph/topo.rs` logs under `--stage-graph-stats` how a big capture's topology differs from the nearest earlier one and why CUDA refused an update. |

a placed layer's slot table replaces the id offset), and `--tp-overlap` of #758 (`micro.rs`: those steps in two micro-batches, each reduce-scatter and all-gather split into a start node and a finish node, so one micro-batch's exchange is on the wire while the GPU computes the other's mixer, or with `ffn` its experts too; the layer flow in `src/model/qwen4/tp_overlap.rs`). ## Request flow

1. A route deserializes the wire request, ignoring unknown fields; JSON errors return 400 in the caller's error format.
2. `server::convert` validates the request and builds a wire-neutral `GenerateRequest`. `AppState::resolve_model` maps the requested name to a served model; if only one model is loaded, any name is accepted to support clients with hard-coded names.
3. `Engine::generate` immediately returns a `TokenStream`; admission, prefill, and decode occur in the engine's loop.
4. The route either collects the stream for non-streaming replies or maps each `TokenEvent` to SSE events:
   OpenAI `chat.completion.chunk`s ending in `[DONE]`, or Anthropic `message_start … message_stop`.
   When `logprobs` are requested, the engine sends `TokenEvent::Logprobs` immediately before the `Text` event for those tokens. These are released together via `engine::stop::LogprobHold` to prevent desynchronization during stop-string hold-back: stopped tokens are omitted, while tokens straddling the stop boundary retain their entry.
5. Each request includes a `CancellationToken`. The route maintains a `DropGuard`, so a client disconnect drops the response stream, cancels the token, and prompts the engine to free the sequence.

## Where the real engine plugs in

A real engine implements the `Engine` trait similarly to `MockEngine`: `generate` tokenizes and applies the chat template
(handled engine-side as both are model-specific), then hands the sequence to a single scheduler task per model. This task
manages the GPU(s), performs continuous batching (chunked prefill and decode under a token budget), and sends
`TokenEvent`s back over a per-sequence channel. Planned components:

- **Paged KV pool** (fixed-size blocks, per-sequence block tables) and a **radix prefix cache**. Hybrid models (such as gated DeltaNet in the Qwen3-Next family) also require a per-sequence recurrent-state slot pool, with
  state snapshots at block boundaries to enable prefix caching.
- **ggml** for GGUF loading and quantized matmuls, and **custom CUDA** for paged attention (not provided by ggml).
- Reasoning (`<think>`) and tool-call parsing convert model text into `TokenEvent::Reasoning` or `TokenEvent::ToolCall`. Both front ends support rendering these (OpenAI `reasoning_content`/`tool_calls` and Anthropic `thinking`/`tool_use`).

## Hardware targets

| Target | GPU | Notes |
|---|---|---|
| DGX Spark | GB10 (sm_121), 128 GB unified LPDDR5X | Clusters over RoCE (ConnectX-7) |
| IBM AC922 | 4x V100-SXM2 16 GB (sm_70), POWER9 ppc64le | NVLink 2.0 to the CPUs, unified memory via ATS; GPU pairs on two NUMA nodes; build with gcc-toolset-12 |

V100 (sm_70) builds need CUDA 12.x (12.2 or newer): CUDA 13 dropped sm_70. CI builds an x86_64 CUDA 12.4
sm_70 binary next to the aarch64 CUDA 13.0 one. On an x86 box with V100s on PCIe (no ATS, often no NUMA
node for the GPUs) the residency layer picks its fallbacks from what the driver reports and logs each once:
experts in plain host memory are registered with the driver (`cuMemHostRegister`) when the GPUs cannot read
pageable memory, pinned host memory uses `CU_MEM_LOCATION_TYPE_HOST` when a GPU has no NUMA node, and,
when the GPUs' node is known, `--numa auto` prefers it instead of binding to it (with no known node the
placement is unchanged).
